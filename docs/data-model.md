# Data model

## Operational tables

`traffic_passages` is the detailed hot record. Its identity for archive verification is `(sensor_id, boot_id, track_id)`. Exports select by `ended_at` for one sensor and database-calendar day and retain every known column. Nullable labeling and timestamp fields remain nullable. Parquet v1 stores JSONB `path_points` as deterministic compact JSON text.

`ten_minute_summaries` is already in production and is currently generated by firmware. A read-only helper provides future server-side aggregation and parity comparison. Do not derive long-window p85 by averaging its bucket p85 values.

`traffic_daily` is a permanent aggregate keyed by `(sensor_id, day)`. It keeps raw sum/count pairs for correct weighted averages and a mergeable 25-bin speed histogram:

- bins 0–5, 5–10, …, 115–120 km/h;
- one overflow bin at 120+ km/h;
- large-window average = `sum(speed_sum_kmh) / sum(speed_count)`;
- approximate percentiles come from the histogram merged across days.

`sensor_health` remains operational telemetry and is not part of detailed-passage retention.

`historical_archives` records object identity, byte count, SHA-256, range, count, and state. Its state is meaningful only when transitions follow the verifier rules. New public tables enable RLS and grant no `anon` or `authenticated` access because an application authorization model was unavailable.

## Aggregation assumptions to verify

The repository did not contain V2 firmware or passage rows from which production strings could be confirmed. `AggregationPolicy` centralizes the current explicit assumptions:

- `quality_status`: `accepted`, `review`, `rejected`;
- counted volume/speed/SNR: `accepted` only;
- `direction`: `approach`, `away` (also seen in current summary data);
- motor vehicle: `car`, `truck`, `bus`, `motorcycle`, `motor_vehicle`;
- micromobility: `bicycle`, `bike`, `scooter`, `micromobility`;
- every other counted class: `unknown`;
- speeding: disabled (`0`) unless an operator supplies a verified threshold.

Confirm these values against the restored firmware and a read-only production inventory before a write backfill. Unknown values are not silently forced into known categories.

## Raw archive concept

The future raw archive contains exact, compressed LD2451 UART batches for model research and forensic replay. It is separate from processed passage Parquet and has its own schema version, boot ID, and sequence number. Raw data must not be used by latency-sensitive APIs.
